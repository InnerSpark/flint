# Usage rules

The short list. Every rule exists because something shipped broken without it.

## Color

- **Use semantic tokens, never primitives,** and never a raw hex.
- **Text on a fill uses its "on" token.** Labels on `action.primary` use `action.onPrimary`. Never type white: in dark mode the fills are light and white text drops to about 1.8:1.
- **Muted text is for secondary information,** never for anything a person must read to finish a task.
- **Placeholders are hints, not labels.** Every field keeps a visible label.
- **Decorative borders are decorative.** `border.default` and `border.strong` never form the only edge of a control. Controls use `border.control`.
- **Feedback families stay together:** an error uses the error surface, border and text, never a mix.

## Type

- Open Sans for everything. Use the type styles, never a hand-set size.
- Nothing below 12px. Body text stays under about 80 characters a line.
- Headings follow document order. Never pick a heading level for its size.

## Space and size

- Spacing stays on the scale: 0, 2, 4, 8, 12, 16, 24, 32, 40, 48, 64.
- Targets are at least 24px (44pt on iOS). Aim for 40px on anything used often.
- Density changes inset and gap only.

## Components

- One primary button per view. Everything else is secondary or text.
- Destructive actions use the danger button and a confirm step.
- Forms use a field with a label, helper and error wired in. Errors replace the helper text and focus moves to the first errored field.
- Dialogs and drawers trap focus, close on Esc and return focus to what opened them.
- Every interactive thing has every state: default, hover, focus, disabled, and where it applies, selected and error.

## Accessibility notes on every screen

- Landmarks, accessible names for icon-only controls, and current, selected and expanded states.
- Live regions: `role="status"` for progress, `role="alert"` for errors.
- Focus order, and where focus goes when something opens or closes.
- What each animation becomes under reduced motion.

The test: can a blind user finish the flow with VoiceOver or NVDA alone?
